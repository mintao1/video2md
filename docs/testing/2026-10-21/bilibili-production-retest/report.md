## 发现的问题

1. **P1：Colab 生命周期或产物传输失败阻断合集产出。** 第 1 集 OCR 会话消失，两集剪辑均失败。日志区分了“GPU 端剪完”与“主任务收到产物”；没有将前者误报为成功交付。具体回收、下载或创建失败的最终根因尚未证明。
2. **P1：已知缺少 clips 后仍消耗正文模型。** 两集剪辑失败后仍调用 organize 和 metadata，最后才因无节段拒绝写盘。真实费用已发生，教材产出为零。相关错误已保留在最终 run 记录。
3. **P1：HTTP 200 空内容重试会漏记先前 usage。** 隔离复现中两次请求应累计 300/100 tokens，系统只记最后一次 200/60。当前生产 `llm.py` 哈希与复现代码一致。生产该轮选帧确有三次尝试，但前两次 usage 未保留，不能反推出少记 token 或金额。
4. **P1：长任务期间重新登录发生换票超时。** 两次真实回调 ReadTimeout，容器内无凭据 token 端点探测也连接失败；最后一次正常登录恢复。会话过期与换票网络故障的最终根因分别未定位。
5. **P2：失败诊断未指向实际依赖故障。** 前端只显示 note 阶段“处理未完成，请重试或凭任务编号联系支持”，没有指出缺少剪辑、Colab 会话或下载错误。失败及费用没有被隐藏，但用户难以选择有效恢复步骤。

约 114 秒源视频在创建后约 30 分钟才观测到失败终态，剪辑阶段约 16 分钟。该数据作为本轮性能观察，不据单次样本声称长期 SLO 违约。

## 漏记缺陷的隔离复现

命令：`backend/.venv/bin/python docs/testing/2026-10-21/bilibili-production-retest/repro_retry_usage.py`。

独立进程实际执行当前 `llm.py` 的 chat、回包解析和用量观测代码；仅替换配置、HTTP 传输、遥测及存储接收缝。不读取凭据，不访问外网，不修改项目 JSON。单请求控制通过，空内容但含 usage 后重试的案例稳定断言失败，退出码 1；证据为 `retry-usage-repro.txt`。

三项诊断候选为重试分支遗漏、回包解析遗漏、汇总接收覆盖。解析控制已证明空回包的 100/40 usage 被正确读取；用量接收缝只收到最终一次调用。结合每轮重置 meta、仅最终成功或耗尽重试时观测的代码，定位为重试用量收口遗漏。每次调用分别观测也符合 [Langfuse 当前最佳实践](https://langfuse.com/docs/observability/best-practices)。这是合成零网络诊断，不是实际生产少记数量；本轮为测试，未执行修复或回填历史账本。
