# 抖音用户主页 → 全部作品出文档

## 架构决策：全部改动收敛在 serve 层（video2md.py），**工作流 YAML 零改动**

理由：工作流已经是「条目展开由 serve 做、各阶段 loop 只轮询 run_id、note loop 按 total 逐条目走」的结构。把博主主页枚举成 entries 后，下游所有 loop 天然兼容。已启用的 Langfuse tracing 也会自动覆盖。

## 实现步骤

### 1. 探测（先做，决定后续路径）
用 yt-dlp 实测该博主主页：`yt-dlp --flat-playlist --dump-single-json --simulate <user_url>`，先无 cookie、失败再加 `--cookies-from-browser chrome`。
- 成功 → 走 yt-dlp 枚举路径
- 失败 → 错误提示「请在 Chrome 登录抖音」（yt-dlp 对抖音用户页的支持不确定，实测为准）

### 2. URL 识别与归一化（video2md.py）
- `normalize_douyin_url` 扩展：识别 `douyin.com/user/<sec_uid>?...`，剥掉 `from_tab_name`/`vid` 等查询参数
- `resolve_url` 对 `/user/` 链接：先 yt-dlp 平铺枚举，失败回退带 Chrome cookies 重试
- entry 映射：`{url: /video/<id> 或 /photo/<id>, id: aweme_id, playlist_index: 信息流序号（新→旧）, playlist_title: 博主名, playlist_id: sec_uid, uploader, media_type: video|image_post}`
  - `media_type` 判定：URL 形态 `/photo/` vs `/video/`，兜底看有无 duration
- `part_items` 语义不变（1-10 = 最新 10 个作品），大博主可切片跑

### 3. 图文帖下载分支（download 阶段）
- `media_type=image_post` 的条目：抓 `douyin.com/photo/<id>` 页内 aweme JSON（复用 `_find_aweme` 递归找 `images[]` 代替 `play_addr.uri`），httpx + Referer 逐图下载到条目目录 `images/img_NNN.jpg`
- 写 `art["images"]`，跳过视频文件

### 4. 图文帖的阶段分支（serve 各 stage）
- `transcribe`：跳过（无音频）
- `frames`：图集直通为 candidates（不解码视频）
- `ocr`：照常跑（vision/gemini），然后把 OCR 文本**按图序合成转录本**写 `art["transcript"]`（`[图1] ...` 标记）→ note loop 无需改动（空转录本会跳过，所以必须有合成）
- `select`：图集全选直通（每个作品图片数有限，不走 LLM 选帧）
- `clips`：跳过（无视频可剪）
- `note`/`kb`：完全复用现有逻辑

### 5. 测试
- `test_resolve.py` 新增：用户主页 URL 归一化、混合条目（视频+图文）media_type 判定、part_items 对用户 feed 的切片
- 冒烟：先 `part_items=1-2` 小跑该博主（1 视频+1 图文），确认两类文档产出，再全量

### 6. 收尾
- 重启 serve 进程（resolve 逻辑跑在 serve 主进程里，必须重启生效；stage 子进程每次新起，自动用新代码）
- README 支持站点表格更新：抖音用户主页（含图文）

## 风险与对策
| 风险 | 对策 |
|---|---|
| yt-dlp 可能枚举不了抖音用户页 | 步骤 1 先实测；不行则报明确错误（需 Chrome 登录抖音）；再不行走页面抓取兜底 |
| 反爬/限流 | cookies 重试 + 明确报错 |
| 图文细节页结构变化 | `_find_aweme` 递归搜索本就鲁棒，失败有明确报错 |
| 老 run 兼容 | 仅新增路径，现有 B站/YouTube/单视频链路不动 |

## 验证方式
Langfuse Cloud `dify-video2md` 项目 Tracing 页实时看每个条目的阶段轨迹（tracing 昨晚已通）。
