# GPU Router：多平台免费算力动态路由（sidecar 代理）

## 目标

不再只有 Colab：新增独立本地代理服务 `gpu_router`（127.0.0.1:9700），把 **ASR 转录 / 节段剪辑 / OCR** 三类负载按「能力优先级列表 + 健康探测 + 熔断冷却 + 手动开关」动态路由到 Colab / Modal / Kaggle / HF ZeroGPU / 国内云（阿里云·百度·超算，通用 HTTP 适配）。video2md 主仓改动极小（只加 HTTP 客户端路径），现有 `V2MD_REMOTE=colab` 等用法完全不变。

> 说明：南京「算力超市」是 LLM-Token 型平台（DeepSeek/豆包 API），不能跑任意 GPU 负载，不纳入路由器（文档中注明，可日后在 Dify 控制台配成 LLM 供应商）。

## 架构

```
video2md (serve :8790)                     gpu_router (:9700)
  V2MD_REMOTE=http://127.0.0.1:9700  ──►   POST /transcribe ─┐
  V2MD_CLIPS_REMOTE=同上             ──►   POST /clips       ├─► 选举→熔断冷却→故障转移
  V2MD_OCR_REMOTE=同上 (新)          ──►   POST /ocr         │     │      │       │
                                     ◄──   GET /status      │  colab   modal   kaggle …
                                           POST /providers/{name}/enable|disable
                                           状态: logs/gpu-providers.json
```

**统一参考服务端**：`gpu_router/reference/app.py` 一个 FastAPI 应用实现 `/ping /transcribe /clips /ocr`（faster-whisper + ffmpeg + RapidOCR——选 RapidOCR 而非 PaddleOCR：ONNX 免装 paddle、中文同源 PP-OCR 模型、各平台零系统依赖）。它是 `colab/cell_server.py` 的超集，三处复用：Colab cell（保留云喇叭隧道入口）、Modal 应用、国内云部署（文档指导）。

## 改动文件（薄客户端）

1. **`video2md/clips.py`**：新增 `remote_cut_clips()`——本地算好剪辑 spec（复用 `_clip_tasks`），POST `/clips`（源片上传或 `direct_url` 字段），收回 tar 解到 attachments，语义与 `colab_cut_clips` 一致（单段失败丢该段、整体失败上抛、不回退本地）。同时把 `colab_cut_clips` 的远端执行段抽成 `colab_exec_clips(video, direct_url, specs, tmp)` 供 router 的 colab provider 复用（行为不变）。
2. **`video2md/runs.py`**：`_stage_clips` 支持 `V2MD_CLIPS_REMOTE=<URL>`；`_stage_ocr` 引擎解析加 `remote`（`V2MD_OCR_REMOTE` 设置且 args 未强制 vision 时生效）。
3. **`video2md/frames.py`**：`ocr_candidates` 加 remote 分支——整条目一次 multipart 批量上传（约 60 帧 / ~12MB），返回 `[{name,text,conf}]`，复用现有 LOW_CONF 过滤与时间线合成。
4. **`video2md/serve.py`**：`_preflight` 在 `V2MD_REMOTE` 为 URL 时改为 GET 路由 `/status` 要求 ok（asr 至少一个可用 provider），colab 直联模式体检保持原样；`_checkpoint` 附带路由快照（2s 超时尽力而为）。
5. **`video2md/transcribe.py`**：不改——`remote_transcribe` 的 `/transcribe` 契约即路由契约，`.env` 指向 9700 即接入。
6. **`.env.example`**：新增路由三开关注释块；**`pyproject.toml`**：加 `fastapi / uvicorn / python-multipart`（`gradio_client` 与 `kaggle` CLI 按需可选，代码内守卫式导入+报错提示）。

## 配置与状态

`gpu_router.json`：
```json
{
  "listen": "127.0.0.1:9700",
  "order": {
    "asr":   ["modal", "colab", "kaggle", "zerogpu"],
    "clips": ["modal", "colab", "kaggle"],
    "ocr":   ["modal", "kaggle", "aliyun"]
  },
  "providers": [
    {"name":"modal",  "kind":"http", "url":"https://xxx.modal.run"},
    {"name":"colab",  "kind":"colab-cli"},
    {"name":"kaggle", "kind":"kaggle"},
    {"name":"zerogpu","kind":"zerogpu", "space":"user/v2md-asr"},
    {"name":"aliyun", "kind":"http", "url":"", "enabled":false}
  ]
}
```
`logs/gpu-providers.json` 运行时态：`{enabled 覆盖, cooldown_until, consecutive_failures, last_error, usage{date: 估 GPU 秒}}`。

**动态开关语义**：请求级选举；错误分类决定冷却时长（quota-日级 20h / quota-周级 4d / auth 1h / 网络·隧道 10min / 任务级不冷却直接换下一家）；每请求每家最多试一次；全灭 → 502 带各家错误摘要（上游沿用现有熔断收口）。`POST /providers/{name}/enable|disable` 持久化手动开关；用量计数落盘（配额加权排序列为 v1.5，文档注明）。**「失败不静默回退本地 CPU」政策不变**——故障转移只发生在 provider 之间。

## 各平台接入要点

| 平台 | 方式 | 一次性准备（需要你的账号） |
|---|---|---|
| Colab | 现有 CLI 会话 + 隧道两种，原样保留 | 已有 |
| Modal | 通用 HTTP（参考服务端 T4，模型 Volume 缓存） | `modal token new` + `modal deploy`，把 URL 填进配置 |
| Kaggle | 批内核（数据集滚动版本传输入，kernels output 拉结果；剪辑支持 direct_url 让内核直连 CDN） | phone 验证 + `~/.kaggle/kaggle.json`；冷启动 3–8min 文档注明 |
| HF ZeroGPU | gradio_client 调参考 Space，仅 ASR | 部署 Space + HF token；日配额几分钟→兜底位 |
| 阿里云/百度/超算 | 通用 HTTP，url 配置即启用 | 按 docs/gpu-router.md 把参考服务端部署到对方 GPU 容器/函数计算 |

## 测试

- `test_router.py`：选举顺序、分类冷却、故障转移、手动开关、状态持久化、配置兼容（假 provider 内存实现）。
- 参考服务端契约测试：FastAPI TestClient + mock 模型层，验证三端点请求/响应形状。
- 客户端测试：`remote_cut_clips` / remote OCR 用 httpx MockTransport 桩验证（含 tar 解包、部分失败语义）。
- 回归：现有 `test_jobs.py / test_resolve.py` 全绿；`V2MD_REMOTE=colab` 路径行为不变。
- 真机冒烟（默认跳过，需凭证）：`GPU_ROUTER_LIVE=modal,kaggle …`，附 `scripts/ocr_compare.py` 抽样验收 OCR 质量。
